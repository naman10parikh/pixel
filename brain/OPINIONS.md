# pixel — Opinions (Taste Stances)

> These are pixel's **opinionated defaults** — the stances that make output *not look AI-generated* and *not break in production*. Each is **ALWAYS X / NEVER Y — because Z [source]**. Some are inherited-and-confirmed energy taste (house style); some are reasoned verdicts from the trade-off matrix (flagged as judgment calls → [[GAPS-AND-DISPUTES]]). A stance without a "because" is just a preference — every one here earns its place. **Hold the line on these; the chairman's flagship is judged on taste, not feature count.**

---

## The house style (inherited from energy, CONFIRMED current by the research)

- **O-HS1 — ALWAYS warm black `#141312`. NEVER pure black `#000` or near-black `#09090b`.** Because pure/untinted black is a top AI-slop tell (impeccable flags it deterministically); warm-black reads editorial and intentional. [ecosystem-00, ecosystem-07]
- **O-HS2 — ALWAYS pair a serif display with a sans body (Instrument Serif + Poppins). NEVER Inter-for-everything.** Because serif+sans pairing is *the single highest-impact anti-AI-generated-look change*; "Inter for everything" is an explicit impeccable slop rule. [ecosystem-00, ecosystem-07]
- **O-HS3 — ALWAYS asymmetric / bento layouts. NEVER symmetric card grids.** Because symmetric grids are the AI-generated pattern; asymmetry reads as designed-by-a-human. [ecosystem-00, ecosystem-07]
- **O-HS4 — NEVER generic AI purple/pink (or purple→blue) gradients, dark glows, bounce/elastic easing, cards-nested-in-cards, or a rounded-square icon tile above every heading.** Because these are the literal impeccable detector rules and energy anti-patterns — a deterministic CI gate now fails the build on them. [ecosystem-07]
- **O-HS5 — NEVER placeholder gray boxes; NEVER pure-white text on dark.** Because gray-box placeholders and untinted gray-on-color are slop tells; use a gradient/mask/icon instead of a gray box, and zinc-100/200 (not #fff) on dark. Tailwind v4.1 `mask-*` + gradient utilities exist precisely to fade images instead of boxing them. [ecosystem-00, ecosystem-02, ecosystem-07]
- **O-HS6 — ALWAYS ONE brand color-moment per page, OKLCH, on Radix 12-step scales.** Because restraint reads premium; OKLCH gives wide-gamut vividness; the 12-step scale has a *purpose per step* (1-2 bg, 3-5 component, 6-8 borders, 9-10 solid, 11-12 text) — that semantic discipline is what makes color systems not-amateur. [ecosystem-00, ecosystem-03]
- **O-HS7 — ALWAYS stream rich cards for tool calls; NEVER a loading spinner without context.** Because "Searching restaurants..." beats a bare spinner — generative UI is the energy design signature and the anti-slop "no spinners without context" rule. [ecosystem-00, ecosystem-05]

## Stack & architecture stances (reasoned verdicts from the trade-off matrix)

- **O1 — ALWAYS target the bleeding edge (Next 16.2 / Tailwind 4.3 / shadcn 4.11 / React 19.2), but be DISCIPLINED about the volatile bits. NEVER ship a stale pattern.** Because currency is the agent's #1 failure mode; but the volatile surfaces (Cache Components, Turbopack) have live bug clusters, so "track the edge" ≠ "trust the edge blindly." This is the top-level posture. [ecosystem-10, ecosystem-09]

- **O2 — NEVER set `cacheComponents: true` globally. ALWAYS adopt `use cache` per-route, with `<Suspense>` around every dynamic read from day one.** Because (mid-2026) it has a live bug cluster — breaks Clerk auth (#85490), React Portals (#85390), CSP nonce (#89754), `<Activity>` (#86577), router cache on dup search-params (#92152). Flipping it on globally and assuming it's free is *the trap*. Re-evaluate as the cluster resolves. *Judgment call (vendor doesn't state "per-route") → [[GAPS-AND-DISPUTES]] §5.* [ecosystem-05, ecosystem-10 Decision 2]

- **O3 — ALWAYS choose Radix (`--base radix`) for a new project now. NEVER migrate to Base UI yet.** Because Radix is the de-facto default, the most-tested shadcn surface, and the unified `radix-ui` package gives clean deps; Base UI removes `asChild` (a global refactor tripwire), changes forms (`Field`) and positioning (Floating UI). Keep Base UI on the watch-list; pay the migration only when shadcn makes it the *default style*. *Judgment call (Base UI is shadcn's signaled future) → [[GAPS-AND-DISPUTES]] §2.* [ecosystem-03, ecosystem-10 Decision 3]

- **O4 — ALWAYS default to Lucide. NEVER ship Phosphor app-wide.** Because Lucide is the shadcn default with ~1× bundle footprint; Phosphor carries **16-18× per-icon overhead** on Next16+Turbopack (6-weight component logic) and its npm is ~13 months stale. Reserve Phosphor for *deliberate weight-hierarchy moments* (a hero where Fill vs Thin conveys state). This refines energy's "use both" with a bundle reason. [ecosystem-03, ecosystem-10 Decision 4]

- **O5 — ALWAYS default Motion to `LazyMotion` + `m` (~4.6KB). NEVER import bare `motion` (~34KB) unless you need everything.** Because the declarative `motion` API can't tree-shake; `LazyMotion` loads feature sets on demand (`domAnimation` +15KB, `domMax` +25KB). Use `useAnimate` mini (2.3KB) for the smallest case. INP budget depends on shipping less JS. [ecosystem-04, ecosystem-10 Decision 5]

- **O6 — ALWAYS use the lowest animation layer that works (CSS > Lenis > GSAP > Motion > Rive > Three). NEVER reach for GSAP for a fade or Motion for a scroll-pin.** Because every layer up costs bundle + complexity. Simple page transition → React 19.2 `<ViewTransition>` (native, zero JS). State/layout → `LazyMotion`. Scroll pin/scrub/snap → GSAP+Lenis (`autoRaf:false`). Branded interactive moment → Rive. 3D only when the brand demands it. [ecosystem-04, ecosystem-10 Decision 5/6]

- **O7 — ALWAYS treat v0/Lovable/Bolt output as an untrusted draft. NEVER merge generated UI without the full ship gate.** Because all three ship **~40-45% vulnerable code**; "light review" ≠ "no review." Generate fast with the v0 Platform API, then finish with design-systems DFS + house style + security + 12-dim + a11y/CWV. **pixel's entire reason to exist over raw v0 is the audit/taste gates, not the generator.** [ecosystem-06, ecosystem-10 Decision 7]

- **O8 — ALWAYS put design tokens in Tailwind v4 `@theme` (CSS), auto-exposed as CSS vars. NEVER reach for `tailwind.config.js` except when a plugin forces a pinned `@config`.** Because `@theme` tokens auto-expose on `:root` and read from React via `var(--color-...)` — perfect for the per-agent BRAND.md color story without JS. This SUPERSEDES energy's "BRAND.md → theme-tokens.json → tailwind.config.ts" flow (the sink is `@theme` now). Use the strict `--color-`/`--font-`/`--breakpoint-` prefixes or the utility silently won't generate. [ecosystem-02, ecosystem-10 Decision 8]

- **O9 — ALWAYS gate every UI on BOTH automated AND manual a11y. NEVER ship on a green axe alone.** Because axe/Lighthouse catch only **~30-40% of WCAG**; impeccable (exit-code) + axe-playwright (0 violations) + lhci budgets are the *necessary* floor, but keyboard + screen-reader + reduced-motion + the 12-dim binary audit are the *sufficient* layer. Automated-only ships inaccessible UIs that pass CI. [ecosystem-07, ecosystem-10 Decision 9]

- **O10 — ALWAYS scaffold + mine reference repos. NEVER fork a starter.** Because forking inherits stale deps (precedent/old-t3 are 12-20mo behind Next 16 / Tailwind v4.3) AND a generic visual identity. Scaffold `shadcn init -t next --base radix`, then mine next-app-router-playground (patterns), ai-chatbot (generative UI/tool-cards), next-forge (monorepo shape), ixartz boilerplate (test/CI/a11y tooling). pixel is hand-crafted. [ecosystem-08, ecosystem-10 Decision 10]

## Quality-bar stances (the binary discipline)

- **O11 — ALWAYS audit on a binary pass/fail (≥10/12 on the design-systems 12-dimension audit). NEVER accept "7/10".** Because "good enough" is how slop ships — either a dimension meets the bar or the fix is explicit. The DFS discovery brief is a HARD GATE: **NO BRIEF = NO DESIGN**; the ICP is a *specific named person*, not a demographic. [ecosystem-06, ecosystem-07]
- **O12 — ALWAYS perfect ONE hero component to 100% before scaling (DFS Hero). NEVER scale a half-baked component across the page.** Because the hero carries ~60% of emotional weight; getting it to 100% first sets the bar everything else inherits. [ecosystem-06]
- **O13 — ALWAYS prefer the codemod/CLI to hand-edits; the agent's job is the GAP the codemod misses. NEVER hand-redo mechanical migration.** Because determinism beats cleverness (Karpathy "surgical changes"); and `shadcn add --dry-run`/`--diff` before writing, because a bad multi-file write can't easily be undone. [ecosystem-09]
- **O14 — ALWAYS verify visually (screenshot + READ it) and read the console (0 hydration warnings). NEVER call a green build "done".** Because "it compiles means nothing" — the silent-failure class (dead middleware, dropped Tailwind styles, hydration mismatch) is invisible to the compiler and to an agent that doesn't look. [ecosystem-09, ecosystem-05]
- **O15 — ALWAYS randomize animation timing delays; keep motion 200-500ms, transform+opacity only, 60fps. NEVER use fixed identical intervals or animate layout properties.** Because fixed 100ms intervals feel robotic (the Stripe CEO literally rewrote code to randomize typing delays); animating non-composited properties drops frames. Respect `prefers-reduced-motion` by *minimizing* non-essential motion, not killing all of it. [ecosystem-04] *(O-F2/O-F3/O-F4 below sharpen the timing + easing + frequency rules with named-practitioner field sources.)*

## Field-sourced taste stances (the named-practitioner layer — verbatim quotes, attributed)

> These come from the two FIELD-INTELLIGENCE passes (`field-*` committed `9a127ff`; `field-craft-*` untracked-then-committed-here) — the layer the ecosystem pass admitted it lacked ([[GAPS-AND-DISPUTES]] §7, now closed). Each is ALWAYS/NEVER + because + **a load-bearing verbatim quote from the person whose work IS the 2026 taste benchmark**. These are the stances average frontend devs (and median-sampling LLMs) miss. The citation chain is preserved: `field file → original author/URL/date`. Where two passes corroborate the same rule independently, that is flagged as the highest-confidence signal.

- **O-F1 — NEVER let the indigo/purple prior surface; ALWAYS override the brand color explicitly (warm-black + a non-purple accent).** Because AI-purple is not a taste choice the model is making — it is a *training-data artifact*: Adam Wathan (Tailwind creator) made every Tailwind UI button `bg-indigo-500`, that color saturated the training corpus, and the model now emits it as the "statistically most correct option." Verbatim (Wathan, X, 2025-08-07, ~684K views): *"I'd like to formally apologize for making every button in Tailwind UI `bg-indigo-500` five years ago, leading to every AI generated UI on earth also being indigo."* This *supersedes* energy's own `react.md` line "Purple theme #6b21a8 primary" — which prescribes the #1 slop color. Extends O-HS4 with the named root cause. [field-craft-01 §3b; field-05 §5 / field-craft-05 §5 — both passes flagged the energy `react.md` purple gap independently → [[GAPS-AND-DISPUTES]] §14]

- **O-F2 — NEVER animate keyboard-initiated actions; ALWAYS frequency-gate motion (animate the novel, never the hundreds-of-times-a-day action).** Because an animation on a repeated action makes it feel slow and disconnected from the user's intent. This is the single highest-confidence taste rule in the whole research set: TWO independent benchmark practitioners state it. Emil Kowalski (built Sonner + Vaul; animations.dev), verbatim: *"never animate keyboard initiated actions"* — *"these actions are repeated sometimes hundreds of times a day, an animation would make them feel slow."* Rauno Freiberg (Staff Design Engineer, Vercel), verbatim: *"Avoid animations on frequent, low-novelty actions."* energy's bible misses this rule entirely — pixel adds it. [field-craft-05 §1 + field-04 §1 (Emil, emilkowal.ski/ui/great-animations); field-craft-02 §1 (Rauno, interfaces.rauno.me)]

- **O-F3 — ALWAYS use `ease-out` (sub-300ms) for entrances/feedback; reach for SPRINGS only when motion is attached to a continuous user input (drag/flick/gesture); NEVER `linear`/`ease-in` on UI, NEVER spring everything.** Because perceived responsiveness comes from a fast start that slows into a soft landing (`ease-out`), and springs survive interruption because — verbatim (Raphael Salaja, "To Spring or Not To Spring", 2025-12-29) — *"easing curves have a predefined start and end in time, whereas springs do not… which [is] why springs survive interruption so well while easing curves tend to fall apart as soon as the user changes their mind."* Emil's rule for the discrete case, verbatim: *"the best type of easing for this purpose is `ease-out`"* and animations *"should also usually be shorter than 300ms."* This SHARPENS O15/energy's "200-500ms": **sub-300ms `ease-out` is the ceiling for direct-manipulation feedback; 200-500ms is for page/hero transitions; the danger is a worker splitting the difference at a sluggish 350ms button.** Deciding variable: motion attached to continuous input → spring; system announcing a discrete change → easing. [field-craft-05 §1 + field-04 §1 (Emil); field-05 §2 / field-craft-04 §2 (Salaja, spring-vs-easing)]

- **O-F4 — ALWAYS make animations interruptible; the boring core (scroll, text input, navigation) must be bulletproof BEFORE any flourish.** Because a non-interruptible animation that blocks re-trigger reads as low craft, and a broken scroll destroys trust no hero animation can buy back. Emil: interruptibility *"helps your animations feel more natural and responsive."* Rauno's taste inversion, verbatim: *"most interactions are brittle and fail under real-world stress. Core interactions like scrolling, text input, and navigation must always work perfectly."* Average devs add a flashy hero; great devs first guarantee the core never breaks. [field-craft-05 §1–§2 (Emil interruptibility, Rauno robustness); field-04 §1–§2]

- **O-F5 — ALWAYS prefer the native CSS primitive when its support floor meets the product's browser matrix; NEVER reflexively `npm i @floating-ui/react`/GSAP/AOS for a job native CSS now does.** Because in 2026 the lowest layer reaches *higher* than it did in 2025 — `:has()` (93%+), container queries (95%+), `sibling-index()` stagger, scroll-driven animations (85%), View Transitions (83%), Anchor Positioning (78%), customizable `<select>` keep the native accessibility/semantics "we previously only got from JavaScript-powered components." The 2025 reflex *"npm i framer-motion / floating-ui / aos" is now the SLOP default*; each has a native replacement for the common case. This SHARPENS energy's "use the lowest layer that works" / O6. CAVEAT (gate per surface): Anchor Positioning + View Transitions need fallbacks on Safari/long-tail — `:has`/container queries are safe unguarded. [field-06 §1 (LogRocket "CSS in 2026" 2026-01-21) / field-craft-06 §1 (codercops "State of CSS 2026" 2026-02-21, with the 50–100KB-JS-removed / TTI −0.8s receipts)]

- **O-F6 — NEVER treat Inter as a *distinctive* choice; ALWAYS reserve neutral grotesques for get-out-of-the-way product/doc UI and use a personality/serif face for display.** Because Inter's ubiquity is now its liability — it reads "template," not "designed." Verbatim (Juan Mantz): *"Inter is the black t-shirt of fonts… I could actually wallpaper my office with SaaS screenshots, and it would create a homogeneous mosaic."* This is the typography case of the slop catalog and CONFIRMS energy's Instrument Serif + Poppins mandate (which is *right*) — but reframes Inter as *neutral-by-design*, not safe-by-default. Distinctiveness is the 2026 differentiator. Reinforces O-HS2. [field-06 §2 (Mantz, design-bootcamp 2024-10-09, thesis mainstream in 2026); field-craft-01 §3d (925studios 2026-06-10 "Inter default → pick one display font")]

- **O-F7 — ALWAYS use `box-shadow`/ring for focus rings (NEVER raw `outline` on rounded elements); ALWAYS gate hover behind `@media (hover: hover)`; ALWAYS ≥16px input font on mobile; NEVER leave dead zones in lists.** Because these are the greppable micro-tells a reviewer spots taste by in two seconds — and they are exactly what median-sampling output omits. Rauno, verbatim: *"Box shadow should be used for focus rings, not outline which won't respect [border] radius"*; *"Hover states should not be visible on touch press; use `@media (hover: hover)`"*; *"Font size for inputs should not be smaller than 16px to prevent iOS zooming on focus"*; *"Interactive elements in a vertical or horizontal list should have no dead areas between each element; instead, increase their padding."* The Vercel Web Interface Guidelines codify the full set (100 rules, agent-runnable) — pixel should adopt them as a hard lint pass: it ALSO adds `tabular-nums` on changing numbers, the `…` character (not `...`), non-breaking spaces (`10&nbsp;MB`), the `transition: all` ban, "never block paste," and "URL reflects state." Extends energy's pre-delivery checklist. [field-craft-02 §1 (Rauno, interfaces.rauno.me); field-04 §5 (Vercel WIG, vercel-labs/web-interface-guidelines)]

- **O-F8 — ALWAYS commit to ONE aesthetic direction WITHIN a surface, but MATCH intensity to surface purpose (marketing/hero = spectacle allowed, even deliberate maximalism; dashboard/app/a11y-first = restraint + bundle discipline). NEVER ship *unmotivated* or *averaged* maximalism.** Because the slop tell is not maximalism per se — it is aurora-on-a-B2B-settings-page (intensity mismatched to purpose) or three half-committed aesthetics at once (the AI-averaging failure). Verbatim resolution (ogblocks 2026): *"the maximalism vs. minimalism debate in 2026 seems resolved not by declaring one winner, but by recognizing that different projects have different needs—landing pages benefit from Aceternity's visual spectacle, while utilitarian dashboards require restraint."* The production pattern: shadcn/ui for app components, Aceternity for marketing. energy's warm-black editorial baseline is ONE valid direction, not the only one — for a bold consumer brand, "controlled boldness" (maximalism that still passes contrast + reduced-motion) is the better call. [field-05 §4 / field-craft-04 §3 (ogblocks + devopus/imanila/Figma-trends-2026); resolves the field-craft-01 §4 open question]
